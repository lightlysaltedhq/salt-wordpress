# Design tokens (§13) — frozen contract

Three tiers, authored in `assets/src/css/app.css` (`@theme`, Tailwind v4):

1. **Primitives** — `--color-neutral-{50..950}`, `--color-primary-{50..950}`
   (+ secondary/accent). Compiled defaults are the NEUTRAL ramp (seed
   `#4b5563`) generated by `salt_derive_ramp()` — the same PHP that derives
   per-site ramps at runtime, so defaults and derivation cannot diverge.
   Per-site values: three admin-set brand colours → `salt_brand_css()` →
   inline `:root` override in `<head>` (nonce-stamped for CSP). No rebuild
   for a brand change; fresh installs render legibly (FAIL03).
2. **Semantic roles** — what components consume (the ONLY tier components
   may reference): `surface`, `surface-alt`, `surface-inverse`, `ink`,
   `ink-muted`, `ink-inverse`, `brand`, `brand-strong`, `brand-tint`,
   `on-brand`, `accent`, `on-accent`, `border`, `focus`,
   `success|warning|error|info`. The focus ring's geometry is
   `--focus-ring-width` and `--focus-ring-offset`, in px, at least 2px and
   1px (design-foundations 3.0.0's `focusIndicator`). Inside a
   `surface-inverse` band the ring gets an `ink.inverse` keyline outside
   it, drawn by salt.css, because the ring alone does not reach 3:1 on
   that ground.
3. **Components** — the Salt contract's stylesheet (salt.css), which reads
   role tokens only. app.css builds no Tailwind utility.

**Dark mode (§13a)** is a semantic-role inversion under
`[data-theme=dark]` — primitives never change, no section has a dark
variant. Enabled per site (option), applied pre-paint by the nonce'd head
script.

**Contrast guarantees:** text-tier steps are clamped via `salt_text_on()`
(AA ≥ 4.5:1 mathematically guaranteed); the CI property test sweeps hues
0–360 asserting derived text passes AA on light AND dark surfaces
(tests/unit/ColorsTest.php). `on-brand` follows the display mode: each
mode points it at `--color-on-primary-{step}` for the step it fills `brand`
with, which `salt_brand_css()` derives per site. The conformance suite
evaluates the contract's contrast rules in every combination of dark, high
contrast and grayscale (tests/conformance/FoundationsConformanceTest.php),
and refuses a colour rule it cannot rank. Section backgrounds are a fixed set of role
tokens (§11) — arbitrary colour is not an editor capability in v1.

**The section band** (tone, dark tone, spacing, width) is the contract's
`markup/section.json`, drawn by `template-parts/components/contract-section.php`
and snapshot-locked (FLEET01).
